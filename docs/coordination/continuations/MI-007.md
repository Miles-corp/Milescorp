## Objectif

Rendre l'activité de MILES visible par l'utilisateur : derniers appels d'outils,
missions exécutées, refus d'autorisation, erreurs — sans jamais exposer de secret
(le journal d'audit `app/tools/audit.py` est déjà expurgé par conception ; à vérifier).

## Contenu proposé

- CLI : `/log [n]` — afficher les n derniers évènements d'audit.
- Web (option, niveau 4 si route consultative) : `GET /log` derrière `_require_session`.
- Source unique : `AuditLogger` existant (aucun double journal).

## Précautions

- Aucune écriture ; niveau 2 tant que la lecture seule d'audit reste dans le périmètre existant.
- Ne pas réintégrer les champs expurgés ; ne pas afficher d'argument sensible.

## Critères de réussite

Tests : `/log` liste les évènements réels, filtre les secrets, limite la taille,
ne casse rien (`/log` sur audit vide = message clair).
